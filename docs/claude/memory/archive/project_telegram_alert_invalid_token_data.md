NTH (polish, not a bug): add a Telegram alert when a lifetime scan yields improper on-chain data — e.g. `NaN`/undefined token `decimals` producing a `NaN` lifetime deposit — for rare/illiquid tokens.

**Why:** decimals are cached **only** as a side effect of the price-gated P&L-tracker init (`bot-loop-detect.js:239-248`: the `position.decimals0/1 = ps.decimals0/1` assignment lives inside `if (price0 > 0 || price1 > 0)`). A token with **no price at init** (e.g. prod NFT #71544 = INCENTIVE `0x1Cf43d…` / impostor-"HEX" `0xeD1Fb376…`, both 18 decimals on-chain, minted 2024-06-21) → block skipped → `position.decimals0/1` undefined → `computeDepositUsd` does `10 ** undefined = NaN` → `a0=NaN a1=NaN → $NaN` → `total = NaN || 0 = 0` → `_recordScanSuccess` sets `ready = false` → `lifetimeScanComplete` never true → **perpetual "Syncing" badge + disabled "All Positions Stats" button** (gate needs ALL running positions ready). User's stance: savvy LP provider recognizes flaky memecoin data; edge case, not urgent.

1. **Heal:** resolve `decimals0/1` through **`getPoolState`** (the codebase's single entry point for on-chain pool/token state — it already validates decimals `[0,77]` via `pool-state-validate.js` + retries RPCs). Decouples decimals from the price-gated init. `_validDecimals` reuses `isIntegerInRange(d,0,77)`. Runs always on full rescan; else only when decimals missing/invalid → short-circuits (no extra RPC) on healthy positions. (An earlier draft added a bespoke `src/lib/token-metadata.js` decimals+symbol resolver — DELETED as a duplication of getPoolState / mirror of its validators. Symbols dropped from scope: they have their own `getTokenSymbol` path.)
2. **Unhealable → auto-stop + Telegram:** "can't heal" = `PoolStateInvalidError` whose `.field` is `decimals0/decimals1` (structural). RPC exhaustion (`PoolStateUnavailableError`) and non-decimals `PoolStateInvalidError` (price/sqrtPrice/tickSpacing) → transient, retry next rescan, NEVER retire (matches pollCycle's pollError tolerance). Structural → set `botState._retireReason` → poll cycle's new `checkRetireRequest` (bot-cycle-drain.js) fires `notify("positionDataInvalid", {reason})` (distinct default-ON dialog event) + returns `{retired:true}` → existing `onRetire` (bot-loop.js:423 → createOnRetire in server-positions.js: status→`stopped`, auto-compound off, `saveConfig`, drop state, `positionMgr.removePosition`).
3. **"Reload Position" reloads ALL data incl. decimals:** already sets `_needsFullRescan=true` + re-fires the scan; the heal's full-rescan branch re-resolves decimals through the SAME code (zero duplication — user mandate). No Reload-specific code needed.
